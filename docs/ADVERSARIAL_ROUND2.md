# 第二轮对抗审计: 解压特例 (2026-10-09)

## 方法
直接攻击 DLL 层 png_decode_only / submit_batch_pngv, 绕过块扫描,
对 zlib 流本身做 10 类恶意输入 + 25 张结构特例 PNG 双路径对比。

## 恶意流注入 (DLL 直调, 期望安全报错非崩溃)

| 输入 | 错误码 | 判定 |
|---|---|---|
| 正常流 | 0 | 基线 ✓ |
| 空流(zlib头尾无数据) | -50(长度不符) | 安全 ✓ |
| 1字节负载 | -50 | 安全 ✓ |
| 短流(解压<期望) | -50 | 安全 ✓ |
| 长流(解压>ocap, 500KB→4MB) | -28(ocap) | 安全 ✓ |
| 错配尺寸 | -28 | 安全 ✓ |
| 截断流(去尾) | -20 | 安全 ✓ |
| 垃圾字节 | -41(zlib头) | 安全 ✓ |
| 空IDAT | -1(参数) | 安全 ✓ |
| 单字节IDAT | -1 | 安全 ✓ |
| 混合批(好+坏) | 批=0, 逐图[0,-40] | **好图隔离 ✓** |

关键: 好图像素完全不受同批坏流影响(逐图错误码隔离正确),
无崩溃/无卡死/无越界写。

## 结构特例 PNG (25张, 双路径逐字节对比)

通过: 21/21 合法文件 GPU==CPU 逐字节一致:
- 空IDAT夹心 / 私有ancillary块 / 100个tEXt
- 单符号huffman / RLE极限258 / stored跨IDAT分片 / 空final块
- 长匹配回引 / 1-entry调色板 / 3-entry bd4 调色板
- 16位灰度tRNS键4种键值 / Adam7 8x8/1x1/2x2/15x17
- 1x10000 / 10000x1 极端比例

规范非法(双方一致拒绝): PLTE-on-RGBA / tRNS-on-RGBA /
双zlib流拼接 / 超24MP头
