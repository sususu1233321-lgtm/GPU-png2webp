# GPU-сжатие изображений — собственный GPU-энкодер WebP + пакетный инструмент

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | **[Русский](README.ru.md)** | [Español](README.es.md)

Сжимает большие коллекции изображений в WebP: **качество и разрешение
практически не меняются, размер — около 10–15% от исходного, метаданные
сохраняются в файле побайтово.**

## Основные возможности

- **Настоящее кодирование на GPU**: видеокодек-уровневый энкодер ключевых
  кадров VP8 выполняет поиск режимов внутриблочного предсказания и
  волновой замкнутый цикл квантования на вашем NVIDIA GPU
  (CUDA / CuPy / NVRTC) — самая тяжёлая часть конвейера; энтропийное
  кодирование исполняется машинным кодом, скомпилированным Numba, на CPU.
- **40+ входных форматов**: PNG / JPEG / WebP (пережатие) / TIFF / GIF /
  JP2 / JXL / AVIF / HEIC / QOI / DDS / BMP и др.; нативная диспетчеризация
  imagecodecs с полным фолбэком на плагины Pillow — экзотические файлы
  тоже конвертируются.
- **Качество на уровне libwebp**: в пределах ±0.3 дБ PSNR при том же уровне
  качества (замер 36–44 дБ на q90, зависит от содержимого).
- **Полное сохранение метаданных**: `tEXt` / `pHYs` / `eXIf` / `iCCP` из PNG
  и EXIF / XMP из JPEG упаковываются в чанки XMP/EXIF/ICCP WebP; каждый
  вывод **перечитывается и сравнивается побайтово**, при несовпадении файл
  автоматически пережимается CPU-движком.
- **Побитово точный альфа-канал**: собственный минимальный VP8L-энкодер без
  потерь (LZ77 + Хаффман) — ни один бит альфы не искажается.
- **Постоянное улучшение сжатия**: пофреймовая адаптация вероятностей
  коэффициентов плюс GPU-треллис (rate-distortion квантование) дают ещё
  −9.0% при идентичных пикселях (корпус из 6722 изображений:
  1073→977 МБ); смешанные размеры объединяются в дополненные пакеты.
- **Проверка каждого файла + CPU-фолбэк**: каждый вывод декодируется заново
  и проверяется (размеры/альфа/метаданные/PSNR ≥ 34 дБ); при провале файл
  автоматически пережимается через Pillow (libwebp).
- **Управление ресурсами**: ограничение числа ядер CPU из интерфейса
  (`--cores N`, 0 = без ограничения); диспетчер памяти автоматически
  сбрасывает скорость при нехватке ОЗУ, защищая систему от зависания.
- **Несколько GPU**: выбор карты в UI или через `--device`; поддерживаются
  GTX 10-й — RTX 40-й серии и Tesla V100, вывод побитово одинаков на всех
  картах. Пропускная способность: ~**150 изображений/с** с полной
  проверкой на V100 (корпус из 6722 штук — 45 секунд), 250+ изображений/с
  без проверки.
- **Экспериментально: GPU-декодирование PNG** (`PNG_GPU=1`): inflate +
  дефильтрация всех вариантов PNG (глубины 1–16, серый/RGB/палитра/
  серый+A/RGBA, чересстрочность Adam7, tRNS) целиком на GPU, с двойной
  проверкой zlib adler32 и CRC32 каждого чанка, побайтово совпадает с
  libpng (исчерпывающе проверено на 1512 комбинациях). По умолчанию
  выключено — идёт настройка производительности.

## Использование

### Графический интерфейс (двойной клик по `dist/GPU压图/GPU压图.exe`)

1. Выберите исходную папку (запоминается); вывод по умолчанию —
   `источник\webp`, оригиналы не изменяются.
2. Ползунок качества (по умолчанию 90), движок (GPU/CPU), карта GPU и
   лимит ядер CPU.
3. Нажмите «开始压缩»: прогресс, скорость, оставшееся время и процент
   экономии обновляются в реальном времени.
4. Опциональное удаление исходных PNG после завершения — с диалогом
   подтверждения.
5. Неконвертированные файлы копируются как есть в подпапку `未转换/`,
   поэтому выходная папка всегда остаётся полным набором.

> Для развёртывания на другом компьютере скопируйте **папку `GPU压图`
> целиком** (не только exe). Windows 10/11 x64; при наличии NVIDIA GPU
> (драйвер 2023+) используется GPU-движок, иначе — идентичный CPU-движок.

### Командная строка

```
GPU压图.exe --src D:\MyPictures --quality 90
Опции:  --dst ПАПКА_ВЫВОДА   --cpu только CPU   --device 0 (номер nvidia-smi)
        --cores N лимит ядер CPU (0 = без лимита)   --recursive с подпапками
        --no-verify отключить попиксельную проверку
GPU压图.exe --diag    самопроверка окружения (GPU/зависимости)
```

### Восстановление метаданных PNG из WebP

```python
from gpuwebp.png_meta import extract_from_webp, restore_png_text_chunks
meta = extract_from_webp(open("out.webp", "rb").read())
chunks = restore_png_text_chunks(meta)   # [(type, raw_payload), ...]
```

## Честные оговорки

- Энкодер собственный (не libwebp); после адаптации вероятностей и треллиса
  при равном PSNR файлы ~на 35% больше, чем у libwebp method=6, зато в 5–8
  раз быстрее. Попиксельная детерминированность сохраняется на всех
  архитектурах GPU.
- VP8-сжатие с потерами использует 4:2:0; сильно насыщенные тонкие линии
  могут слегка размягчаться по цвету на q90 — поднимите качество до 95.
- Требуется NVIDIA GPU (CUDA 12.x); без неё всё выполняется на CPU
  (Pillow).
- GPU-декодирование PNG — экспериментальная функция (выключена по
  умолчанию): корректность исчерпывающе проверена, настройка скорости
  продолжается.
